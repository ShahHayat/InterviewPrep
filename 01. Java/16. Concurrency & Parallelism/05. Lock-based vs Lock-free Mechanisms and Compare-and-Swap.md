## Introduction

This document explores the fundamental differences between lock-based and lock-free concurrency mechanisms. We'll examine how Compare-and-Swap operations enable lock-free programming and discuss their practical applications in high-performance concurrent systems.

### 🎯 **What You'll Learn**
- **Lock-based vs Lock-free**: Two fundamentally different approaches to thread safety
- **Compare-and-Swap (CAS)**: The atomic operation that makes lock-free programming possible
- **Atomic Classes**: Java's built-in lock-free data structures
- **Performance Trade-offs**: When to use each approach

### 💡 **Simple Analogy**
Think of the difference like **two approaches to sharing a bathroom**:
- **Lock-based** = Using a door lock (only one person at a time, others wait)
- **Lock-free** = Using optimistic approach (try to enter, back off if occupied, retry)
- **CAS** = The mechanism that checks "is bathroom empty?" and "enter if empty" atomically

## Lock-based Mechanisms

**🔧 Technical Overview - Lock-based Synchronization Architecture**:
- **Mutual Exclusion**: Lock-based mechanisms ensure only one thread can access critical sections at a time
- **Blocking Semantics**: Threads that cannot acquire locks are blocked until the lock becomes available
- **Context Switching**: OS kernel involvement in thread blocking/unblocking causes expensive context switches
- **Priority Inheritance**: Some lock implementations support priority inheritance to prevent priority inversion
- **Fairness Policies**: Locks can be fair (FIFO) or unfair (performance-optimized) in thread scheduling
- **Deadlock Susceptibility**: Multiple locks can create circular dependencies leading to deadlocks
- **Memory Barriers**: Lock acquisition/release establishes happens-before relationships for memory consistency

### Characteristics of Lock-based Synchronization

**🔧 Technical Deep Dive - Lock-based Implementation Details**:
- **Monitor Pattern**: Java's synchronized keyword implements monitor-based synchronization
- **JVM Lock Optimization**: Biased locking, thin locks, and fat locks provide performance optimizations
- **OS Integration**: Heavy locks use OS mutex primitives for blocking and scheduling
- **Memory Ordering**: Lock operations provide full memory barriers ensuring visibility and ordering
- **Exception Safety**: Synchronized blocks automatically release locks even when exceptions occur
- **Reentrancy Support**: Java locks are reentrant, allowing same thread to acquire lock multiple times
- **Contention Handling**: Under high contention, threads form queues and may experience convoy effects

```java
public class LockBasedCounter {
    private final Object lock = new Object();
    private volatile int count = 0;
    
    // Lock-based increment
    public void increment() {
        synchronized (lock) {
            count++; // Critical section
        }
    }
    
    // Lock-based decrement
    public void decrement() {
        synchronized (lock) {
            count--; // Critical section
        }
    }
    
    public int get() {
        synchronized (lock) {
            return count;
        }
    }
    
    // Demonstrates blocking behavior
    public void longOperation() {
        synchronized (lock) {
            try {
                System.out.println(Thread.currentThread().getName() + " acquired lock");
                Thread.sleep(2000); // Long operation blocks other threads
                count += 10;
                System.out.println(Thread.currentThread().getName() + " releasing lock");
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
    }
    
    public static void main(String[] args) throws InterruptedException {
        LockBasedCounter counter = new LockBasedCounter();
        
        // Start a long operation
        Thread longThread = new Thread(counter::longOperation, "LongOperation");
        longThread.start();
        
        Thread.sleep(100); // Ensure long operation starts first
        
        // These threads will be blocked
        Thread[] blockedThreads = new Thread[3];
        for (int i = 0; i < blockedThreads.length; i++) {
            blockedThreads[i] = new Thread(() -> {
                System.out.println(Thread.currentThread().getName() + " trying to increment");
                counter.increment();
                System.out.println(Thread.currentThread().getName() + " increment completed");
            }, "BlockedThread-" + i);
            blockedThreads[i].start();
        }
        
        // Wait for all threads
        longThread.join();
        for (Thread thread : blockedThreads) {
            thread.join();
        }
        
        System.out.println("Final count: " + counter.get());
    }
}
```

### Problems with Lock-based Mechanisms

**🔧 Technical Deep Dive - Lock-based Problems and Root Causes**:
- **Deadlock Formation**: Circular wait conditions when multiple threads acquire locks in different orders
- **Priority Inversion**: High-priority threads blocked by low-priority threads holding required locks
- **Convoy Effect**: Threads queued behind a slow lock holder, reducing overall throughput
- **Lock Contention**: Multiple threads competing for same lock cause serialization bottlenecks
- **Context Switching Overhead**: Kernel involvement in blocking/unblocking adds ~1000+ CPU cycles
- **Memory Coherency**: Cache line bouncing between cores accessing shared lock variables
- **Thundering Herd**: Multiple threads waking up simultaneously when lock is released

```java
import java.util.concurrent.locks.ReentrantLock;

public class LockBasedProblems {
    private final ReentrantLock lock1 = new ReentrantLock();
    private final ReentrantLock lock2 = new ReentrantLock();
    
    // Deadlock scenario
    public void method1() {
        lock1.lock();
        try {
            System.out.println(Thread.currentThread().getName() + " acquired lock1");
            Thread.sleep(100);
            
            lock2.lock();
            try {
                System.out.println(Thread.currentThread().getName() + " acquired lock2");
                // Do work
            } finally {
                lock2.unlock();
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            lock1.unlock();
        }
    }
    
    public void method2() {
        lock2.lock();
        try {
            System.out.println(Thread.currentThread().getName() + " acquired lock2");
            Thread.sleep(100);
            
            lock1.lock();
            try {
                System.out.println(Thread.currentThread().getName() + " acquired lock1");
                // Do work
            } finally {
                lock1.unlock();
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            lock2.unlock();
        }
    }
    
    // Priority inversion example
    private final Object sharedResource = new Object();
    
    public void lowPriorityTask() {
        synchronized (sharedResource) {
            System.out.println("Low priority task holding resource");
            try {
                Thread.sleep(3000); // Long operation
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
    }
    
    public void highPriorityTask() {
        System.out.println("High priority task waiting for resource");
        synchronized (sharedResource) {
            System.out.println("High priority task got resource");
        }
    }
    
    public static void main(String[] args) throws InterruptedException {
        LockBasedProblems problems = new LockBasedProblems();
        
        // Demonstrate deadlock
        System.out.println("=== Deadlock Demonstration ===");
        Thread thread1 = new Thread(problems::method1, "Thread-1");
        Thread thread2 = new Thread(problems::method2, "Thread-2");
        
        thread1.start();
        thread2.start();
        
        // Wait a bit to see if deadlock occurs
        Thread.sleep(2000);
        
        if (thread1.isAlive() || thread2.isAlive()) {
            System.out.println("Deadlock detected! Interrupting threads...");
            thread1.interrupt();
            thread2.interrupt();
        }
        
        thread1.join();
        thread2.join();
        
        // Demonstrate priority inversion
        System.out.println("\n=== Priority Inversion Demonstration ===");
        Thread lowPriority = new Thread(problems::lowPriorityTask, "LowPriority");
        Thread highPriority = new Thread(problems::highPriorityTask, "HighPriority");
        
        lowPriority.setPriority(Thread.MIN_PRIORITY);
        highPriority.setPriority(Thread.MAX_PRIORITY);
        
        lowPriority.start();
        Thread.sleep(100); // Let low priority acquire resource
        highPriority.start();
        
        lowPriority.join();
        highPriority.join();
    }
```

## Lock-free Mechanisms

**🔧 Technical Overview - Lock-free Programming Fundamentals**:
- **Non-blocking Algorithms**: Threads never block waiting for other threads to complete operations
- **Atomic Primitives**: Built on hardware-supported atomic operations like Compare-and-Swap (CAS)
- **Memory Ordering**: Uses memory barriers and ordering constraints to ensure consistency
- **Progress Guarantees**: Provides wait-freedom, lock-freedom, or obstruction-freedom guarantees
- **ABA Problem**: Potential issue where values change and revert, requiring careful handling
- **Memory Management**: Requires special techniques for safe memory reclamation (hazard pointers, epochs)
- **Retry Loops**: Failed operations are retried rather than blocking, using exponential backoff

### Understanding Lock-free Programming

**🔧 Technical Deep Dive - Lock-free Implementation Mechanics**:
- **Hardware Atomicity**: Leverages CPU instructions like CMPXCHG (x86) for atomic operations
- **Memory Consistency Models**: Relies on acquire/release semantics for proper ordering
- **Linearizability**: Operations appear to occur atomically at some point during execution
- **Wait-Free vs Lock-Free**: Wait-free guarantees completion in finite steps; lock-free guarantees system progress
- **Contention Handling**: Uses backoff strategies and helping mechanisms under high contention
- **Cache Coherency**: Minimizes cache line sharing to reduce inter-core communication overhead
- **False Sharing**: Careful data structure layout prevents performance degradation from cache conflicts

Lock-free programming uses atomic operations to achieve thread safety without locks, eliminating many lock-related problems.

```java
import java.util.concurrent.atomic.AtomicReference;

public class LockFreeStack<T> {
    private final AtomicReference<Node<T>> head = new AtomicReference<>();
    
    private static class Node<T> {
        final T data;
        final Node<T> next;
        
        Node(T data, Node<T> next) {
            this.data = data;
            this.next = next;
        }
    }
    
    public void push(T item) {
        Node<T> newNode = new Node<>(item, null);
        Node<T> currentHead;
        
        do {
            currentHead = head.get();
            newNode.next = currentHead;
        } while (!head.compareAndSet(currentHead, newNode));
        
        System.out.println(Thread.currentThread().getName() + " pushed: " + item);
    }
    
    public T pop() {
        Node<T> currentHead;
        Node<T> newHead;
        
        do {
            currentHead = head.get();
            if (currentHead == null) {
                return null; // Stack is empty
            }
            newHead = currentHead.next;
        } while (!head.compareAndSet(currentHead, newHead));
        
        System.out.println(Thread.currentThread().getName() + " popped: " + currentHead.data);
        return currentHead.data;
    }
    
    public boolean isEmpty() {
        return head.get() == null;
    }
    
    public void printStack() {
        Node<T> current = head.get();
        System.out.print("Stack contents: ");
        while (current != null) {
            System.out.print(current.data + " ");
            current = current.next;
        }
        System.out.println();
    }
    
    public static void main(String[] args) throws InterruptedException {
        LockFreeStack<Integer> stack = new LockFreeStack<>();
        
        // Producer threads
        Thread[] producers = new Thread[3];
        for (int i = 0; i < producers.length; i++) {
            final int producerId = i;
            producers[i] = new Thread(() -> {
                for (int j = 0; j < 5; j++) {
                    stack.push(producerId * 10 + j);
                    try {
                        Thread.sleep(100);
                    } catch (InterruptedException e) {
                        Thread.currentThread().interrupt();
                        break;
                    }
                }
            }, "Producer-" + i);
        }
        
        // Consumer threads
        Thread[] consumers = new Thread[2];
        for (int i = 0; i < consumers.length; i++) {
            consumers[i] = new Thread(() -> {
                for (int j = 0; j < 7; j++) {
                    Integer item = stack.pop();
                    if (item == null) {
                        System.out.println(Thread.currentThread().getName() + " found empty stack");
                        break;
                    }
                    try {
                        Thread.sleep(200);
                    } catch (InterruptedException e) {
                        Thread.currentThread().interrupt();
                        break;
                    }
                }
            }, "Consumer-" + i);
        }
        
        // Start all threads
        for (Thread producer : producers) {
            producer.start();
        }
        
        Thread.sleep(500); // Let producers add some items
        
        for (Thread consumer : consumers) {
            consumer.start();
        }
        
        // Wait for completion
        for (Thread producer : producers) {
            producer.join();
        }
        for (Thread consumer : consumers) {
            consumer.join();
        }
        
        stack.printStack();
    }
```

## Compare-and-Swap (CAS)

**🔧 Technical Overview - Compare-and-Swap Architecture**:
- **Atomic Instruction**: CAS is a single CPU instruction that atomically compares and updates a memory location
- **Three-Operand Operation**: Takes memory location, expected value, and new value as parameters
- **Success Indication**: Returns boolean indicating whether the swap occurred
- **Memory Ordering**: Provides sequential consistency or configurable memory ordering semantics
- **Hardware Support**: Implemented by CPU instructions like CMPXCHG (x86), LDREX/STREX (ARM)
- **ABA Vulnerability**: Can suffer from ABA problem where value changes and reverts between operations
- **Retry Semantics**: Failed CAS operations typically retry in a loop until success

### Understanding CAS Operations

**🔧 Technical Deep Dive - CAS Implementation and Mechanics**:
- **CPU Instruction Mapping**: Java's CAS maps to native CPU atomic instructions via JNI/intrinsics
- **Memory Barriers**: CAS operations include implicit memory barriers for proper ordering
- **Cache Coherency Protocol**: Ensures atomicity across multiple CPU cores using MESI protocol
- **Bus Locking**: May use bus locks or cache locks depending on CPU architecture and alignment
- **Spurious Failures**: Can fail due to cache coherency protocols even when expected value matches
- **Contention Handling**: Performance degrades under high contention due to cache line bouncing
- **Word Alignment**: Requires proper memory alignment for atomic operations on most architectures

### Advanced CAS Usage

**🔧 Technical Deep Dive - Advanced CAS Patterns and Solutions**:
- **ABA Problem Mitigation**: Use AtomicStampedReference or AtomicMarkableReference for version control
- **Helping Mechanisms**: Implement protocols where threads help complete other threads' operations
- **Backoff Strategies**: Use exponential backoff, random backoff, or adaptive backoff under contention

```java
    // Lock-free linked list node
    static class LockFreeLinkedList<T> {
        private final AtomicReference<Node<T>> head = new AtomicReference<>();
        
        private static class Node<T> {
            final T data;
            final AtomicReference<Node<T>> next = new AtomicReference<>();
            
            Node(T data) {
                this.data = data;
            }
        }
        
        public boolean add(T item) {
            Node<T> newNode = new Node<>(item);
            
            while (true) {
                Node<T> currentHead = head.get();
                newNode.next.set(currentHead);
                
                if (head.compareAndSet(currentHead, newNode)) {
                    System.out.println("Added: " + item + " by " + 
                                     Thread.currentThread().getName());
                    return true;
                }
                // CAS failed, retry
            }
        }
        
        public boolean remove(T item) {
            while (true) {
                Node<T> current = head.get();
                
                if (current == null) {
                    return false; // List is empty
                }
                
                if (current.data.equals(item)) {
                    // Remove head
                    Node<T> next = current.next.get();
                    if (head.compareAndSet(current, next)) {
                        System.out.println("Removed: " + item + " by " + 
                                         Thread.currentThread().getName());
                        return true;
                    }
                    // CAS failed, retry
                } else {
                    // Look for item in the rest of the list
                    Node<T> prev = current;
                    Node<T> node = current.next.get();
                    
                    while (node != null) {
                        if (node.data.equals(item)) {
                            Node<T> next = node.next.get();
                            if (prev.next.compareAndSet(node, next)) {
                                System.out.println("Removed: " + item + " by " + 
                                                 Thread.currentThread().getName());
                                return true;
                            }
                            // CAS failed, restart from head
                            break;
                        }
                        prev = node;
                        node = node.next.get();
                    }
                    
                    if (node == null) {
                        return false; // Item not found
                    }
                }
            }
        }

            Node<T> current = head.get();
            System.out.print("List: ");
            while (current != null) {
                System.out.print(current.data + " ");
                current = current.next.get();
            }
            System.out.println();
        }
```

## Advantages and Disadvantages

**🔧 Technical Analysis - Performance and Design Trade-offs**:

### Lock-based vs Lock-free Comparison

**🔧 Technical Deep Dive - Detailed Performance Analysis**:

| Aspect | Lock-based | Lock-free | Technical Details |
|--------|------------|-----------|-------------------|
| **Blocking** | Threads can block indefinitely | Non-blocking, always makes progress | **Lock-based**: Uses OS scheduler for blocking (~1000+ cycles); **Lock-free**: Busy-waiting with exponential backoff |
| **Deadlock** | Possible with multiple locks | Impossible | **Lock-based**: Susceptible to circular wait conditions; **Lock-free**: Uses atomic operations without lock dependencies |
| **Priority Inversion** | Can occur | Does not occur | **Lock-based**: Low-priority thread holding lock blocks high-priority; **Lock-free**: Operations complete independently of thread priority |
| **Performance** | Can be slow due to contention | Generally faster, especially under contention | **Lock-based**: Context switch ~1000+ cycles; **Lock-free**: CAS operation ~10-50 cycles uncontended |
| **Complexity** | Easier to understand and debug | More complex, harder to get right | **Lock-based**: Familiar synchronization model; **Lock-free**: Requires deep memory model understanding |
| **Memory Usage** | Lock objects consume memory | Lower memory overhead | **Lock-based**: ~48-96 bytes per lock object; **Lock-free**: ~16-32 bytes per atomic variable |
| **Composability** | Difficult to compose operations | Better composability | **Lock-based**: Lock ordering issues, nested locking; **Lock-free**: Operations compose naturally without dependencies |
| **Fairness** | Can provide fairness guarantees | No inherent fairness | **Lock-based**: FIFO queues possible; **Lock-free**: May cause starvation under high contention |

### CAS Operation Characteristics

| Aspect | Advantages | Disadvantages | Technical Details |
|--------|------------|---------------|-------------------|
| **Performance** | Fast, single atomic instruction | Can have high retry overhead | **Uncontended**: ~10-20 CPU cycles; **Contended**: ~100-1000+ cycles with retry loops |
| **Scalability** | Scales well with CPU cores | Performance degrades under extreme contention | **Linear scaling**: Up to 8-16 cores; **Degradation**: Cache coherency overhead dominates |
| **ABA Problem** | Can occur without proper handling | Requires careful design or stamped references | **Pattern**: Value A→B→A appears unchanged; **Solutions**: Version stamps, hazard pointers |
| **Memory Model** | Provides strong consistency guarantees | Requires understanding of memory ordering | **Default**: Sequential consistency; **Variants**: Acquire/release semantics for optimization |

```java
        private final Object syncLock = new Object();
        private long synchronizedCounter = 0;
        
        private final AtomicLong atomicCounter = new AtomicLong(0);
        private final LongAdder longAdderCounter = new LongAdder();
        
        // Synchronized version
        public void incrementSynchronized() {
            synchronized (syncLock) {
                synchronizedCounter++;
            }
        }
        
        public long getSynchronized() {
            synchronized (syncLock) {
                return synchronizedCounter;
            }
        }
        
        // Atomic version
        public void incrementAtomic() {
            atomicCounter.incrementAndGet();
        }
        
        public long getAtomic() {
            return atomicCounter.get();
        }
        
        // LongAdder version (best for high contention)
        public void incrementLongAdder() {
            longAdderCounter.increment();
        }
        
        public long getLongAdder() {
            return longAdderCounter.sum();
        }
    }
    
    // Distributed counter service
    static class DistributedCounterService {
        private final ConcurrentHashMap<String, AtomicLong> counters = new ConcurrentHashMap<>();
        private final AtomicLong totalOperations = new AtomicLong(0);
        
        public long increment(String counterName) {
            AtomicLong counter = counters.computeIfAbsent(counterName, k -> new AtomicLong(0));
            long newValue = counter.incrementAndGet();
            totalOperations.incrementAndGet();
            return newValue;
        }
        
        public long decrement(String counterName) {
            AtomicLong counter = counters.computeIfAbsent(counterName, k -> new AtomicLong(0));
            long newValue = counter.decrementAndGet();
            totalOperations.incrementAndGet();
            return newValue;
        }
        
        public long addAndGet(String counterName, long delta) {
            AtomicLong counter = counters.computeIfAbsent(counterName, k -> new AtomicLong(0));
            long newValue = counter.addAndGet(delta);
            totalOperations.incrementAndGet();
            return newValue;
        }
        
        public long get(String counterName) {
            AtomicLong counter = counters.get(counterName);
            return counter != null ? counter.get() : 0;
        }
        
        public void reset(String counterName) {
            AtomicLong counter = counters.get(counterName);
            if (counter != null) {
                counter.set(0);
                totalOperations.incrementAndGet();
            }
        }
```

```java
import java.util.concurrent.atomic.AtomicReference;
import java.util.concurrent.atomic.AtomicInteger;

public class LockFreeMessageQueue<T> {
    
    private static class Node<T> {
        volatile T data;
        volatile Node<T> next;
        
        Node(T data) {
            this.data = data;
        }
    }
    
    private final AtomicReference<Node<T>> head;
    private final AtomicReference<Node<T>> tail;
    private final AtomicInteger size = new AtomicInteger(0);
    
    public LockFreeMessageQueue() {
        Node<T> dummy = new Node<>(null);
        head = new AtomicReference<>(dummy);
        tail = new AtomicReference<>(dummy);
    }
    
    public boolean offer(T item) {
        if (item == null) {
            throw new NullPointerException("Item cannot be null");
        }
        
        Node<T> newNode = new Node<>(item);
        
        while (true) {
            Node<T> currentTail = tail.get();
            Node<T> tailNext = currentTail.next;
            
            if (currentTail == tail.get()) { // Consistency check
                if (tailNext == null) {
                    // Try to link new node at the end of the list
                    if (compareAndSetNext(currentTail, null, newNode)) {
                        // Successfully linked, now move tail
                        tail.compareAndSet(currentTail, newNode);
                        size.incrementAndGet();
                        System.out.println("Enqueued: " + item + " by " + 
                                         Thread.currentThread().getName());
                        return true;
                    }
                } else {
                    // Tail is lagging, try to advance it
                    tail.compareAndSet(currentTail, tailNext);
                }
            }
        }
    }
    
    public T poll() {
        while (true) {
            Node<T> currentHead = head.get();
            Node<T> currentTail = tail.get();
            Node<T> headNext = currentHead.next;
            
            if (currentHead == head.get()) { // Consistency check
                if (currentHead == currentTail) {
                    if (headNext == null) {
                        // Queue is empty
                        return null;
                    }
                    // Tail is lagging, try to advance it
                    tail.compareAndSet(currentTail, headNext);
                } else {
                    if (headNext == null) {
                        // Inconsistent state, retry
                        continue;
                    }
                    
                    // Read data before CAS
                    T data = headNext.data;
                    
                    // Try to move head to next node
                    if (head.compareAndSet(currentHead, headNext)) {
                        size.decrementAndGet();
                        System.out.println("Dequeued: " + data + " by " + 
                                         Thread.currentThread().getName());
                        return data;
                    }
                }
            }
        }
    }
    
    public T peek() {
        while (true) {
            Node<T> currentHead = head.get();
            Node<T> currentTail = tail.get();
            Node<T> headNext = currentHead.next;
            
            if (currentHead == head.get()) {
                if (currentHead == currentTail) {
                    if (headNext == null) {
                        return null; // Queue is empty
                    }
                    tail.compareAndSet(currentTail, headNext);
                } else {
                    if (headNext == null) {
                        continue;
                    }
                    return headNext.data;
                }
            }
        }
    }
    
    public int size() {
        return size.get();
    }
    
    public boolean isEmpty() {
        return peek() == null;
    }
    
    // Atomic CAS operation for next pointer
    private boolean compareAndSetNext(Node<T> node, Node<T> expect, Node<T> update) {
        // In real implementation, this would use sun.misc.Unsafe or VarHandle
        // For demonstration, we'll use a simple approach
        synchronized (node) {
            if (node.next == expect) {
                node.next = update;
                return true;
            }
            return false;
        }
    }
```

```java
    private volatile int size = 0;

        final K key;
        volatile V value;
        volatile Node<K, V> next;
        final int hash;
        
        Node(K key, V value, int hash, Node<K, V> next) {
            this.key = key;
            this.value = value;
            this.hash = hash;
            this.next = next;
        }

        this.table = new AtomicReferenceArray<>(DEFAULT_CAPACITY);
        this.threshold = (int) (DEFAULT_CAPACITY * LOAD_FACTOR);

    private int hash(K key) {
        if (key == null) return 0;
        int h = key.hashCode();
        return h ^ (h >>> 16);
    }
    
    private int indexFor(int hash, int length) {
        return hash & (length - 1);
    }

        int hash = hash(key);
        AtomicReferenceArray<Node<K, V>> currentTable = table;
        int index = indexFor(hash, currentTable.length());

            if (node.hash == hash && (node.key == key || 
                (key != null && key.equals(node.key)))) {
                return node.value;
            }
            node = node.next;
        }
        return null;

            int index = indexFor(hash, currentTable.length());

            Node<K, V> node = head;
            while (node != null) {
                if (node.hash == hash && (node.key == key || 
                    (key != null && key.equals(node.key)))) {
                    // Key exists, update value
                    V oldValue = node.value;
                    if (!onlyIfAbsent) {
                        node.value = value;
                    }
                    return oldValue;
                }
                node = node.next;
            }

            Node<K, V> newNode = new Node<>(key, value, hash, head);

                size++;
                
                // Check if resize is needed

                    resize();
                }
                
                System.out.println("Put: " + key + "=" + value + " by " + 
                                 Thread.currentThread().getName());
                return null;
            }
            // CAS failed, retry
        }

    public V remove(K key) {
        int hash = hash(key);
        
        while (true) {
            AtomicReferenceArray<Node<K, V>> currentTable = table;
            int index = indexFor(hash, currentTable.length());
            
            Node<K, V> head = currentTable.get(index);
            
            if (head == null) {
                return null; // Key not found
            }
            
            // Check if head node is the one to remove
            if (head.hash == hash && (head.key == key || 
                (key != null && key.equals(head.key)))) {
                
                if (currentTable.compareAndSet(index, head, head.next)) {
                    size--;
                    System.out.println("Removed: " + key + " by " + 
                                     Thread.currentThread().getName());
                    return head.value;
                }
                // CAS failed, retry
                continue;
            }
            
            // Search in the rest of the list
            Node<K, V> prev = head;
            Node<K, V> current = head.next;
            
            while (current != null) {
                if (current.hash == hash && (current.key == key || 
                    (key != null && key.equals(current.key)))) {
                    
                    // Try to remove current node
                    if (compareAndSetNext(prev, current, current.next)) {
                        size--;
                        System.out.println("Removed: " + key + " by " + 
                                         Thread.currentThread().getName());
                        return current.value;
                    }
                    // CAS failed, restart from head
                    break;
                }
                prev = current;
                current = current.next;
            }
            
            if (current == null) {
                return null; // Key not found
            }
        }
    }

        // Simplified implementation - in real code, use VarHandle or Unsafe
        synchronized (node) {
            if (node.next == expect) {
                node.next = update;
                return true;
            }
            return false;
        }
    }

        int newCapacity = oldCapacity << 1;

                Node<K, V> newHead = newTable.get(newIndex);
                Node<K, V> newNode = new Node<>(head.key, head.value, head.hash, newHead);
                newTable.set(newIndex, newNode);
                
                head = next;
            }
        }
        
        table = newTable;
        threshold = (int) (newCapacity * LOAD_FACTOR);
        
        System.out.println("Resized table to capacity: " + newCapacity);
    }
```

```java
import java.util.concurrent.atomic.AtomicReference;
import java.util.concurrent.atomic.AtomicLong;
import java.util.concurrent.atomic.AtomicBoolean;

public class LockFreeBackpressureQueue<T> {
    
    private static final int DEFAULT_CAPACITY = 1024;
    
    private final Node<T>[] buffer;
    private final int capacity;
    private final int mask;
    
    private final AtomicLong writeSequence = new AtomicLong(0);
    private final AtomicLong readSequence = new AtomicLong(0);
    private final AtomicLong cachedReadSequence = new AtomicLong(0);
    private final AtomicLong cachedWriteSequence = new AtomicLong(0);
    
    private final AtomicBoolean backpressureActive = new AtomicBoolean(false);
    private final AtomicLong droppedItems = new AtomicLong(0);
    
    static class Node<T> {
        volatile T data;
        volatile long sequence = -1;
        
        Node() {}
    }
    
    @SuppressWarnings("unchecked")
    public LockFreeBackpressureQueue(int capacity) {
        if (Integer.bitCount(capacity) != 1) {
            throw new IllegalArgumentException("Capacity must be a power of 2");
        }
        
        this.capacity = capacity;
        this.mask = capacity - 1;
        this.buffer = new Node[capacity];
        
        for (int i = 0; i < capacity; i++) {
            buffer[i] = new Node<>();
            buffer[i].sequence = i;
        }
    }
    
    public LockFreeBackpressureQueue() {
        this(DEFAULT_CAPACITY);
    }
    
    public boolean offer(T item) {
        return offer(item, false);
    }
    
    public boolean offer(T item, boolean dropOnBackpressure) {
        if (item == null) {
            throw new NullPointerException("Item cannot be null");
        }
        
        long currentWriteSeq;
        Node<T> node;
        
        while (true) {
            currentWriteSeq = writeSequence.get();
            node = buffer[(int) (currentWriteSeq & mask)];
            long nodeSeq = node.sequence;
            long diff = nodeSeq - currentWriteSeq;
            
            if (diff == 0) {
                // Slot is available
                if (writeSequence.compareAndSet(currentWriteSeq, currentWriteSeq + 1)) {
                    break;
                }
            } else if (diff < 0) {
                // Buffer is full
                if (dropOnBackpressure) {
                    droppedItems.incrementAndGet();
                    backpressureActive.set(true);
                    System.out.println("Dropped item due to backpressure: " + item + 
                                     " by " + Thread.currentThread().getName());
                    return false;
                } else {
                    // Check if we should activate backpressure
                    long cachedRead = cachedReadSequence.get();
                    if (currentWriteSeq - cachedRead >= capacity) {
                        // Update cached read sequence
                        cachedReadSequence.set(readSequence.get());
                        if (currentWriteSeq - cachedReadSequence.get() >= capacity) {
                            backpressureActive.set(true);
                            return false; // Buffer is truly full
                        }
                    }
                    
                    // Yield and retry
                    Thread.yield();
                }
            }
        }
        
        // Store the item
        node.data = item;
        node.sequence = currentWriteSeq + 1;
        
        backpressureActive.set(false);
        
        System.out.println("Offered: " + item + " at sequence " + currentWriteSeq + 
                         " by " + Thread.currentThread().getName());
        return true;
    }
    
    public T poll() {
        long currentReadSeq;
        Node<T> node;
        
        while (true) {
            currentReadSeq = readSequence.get();
            node = buffer[(int) (currentReadSeq & mask)];
            long nodeSeq = node.sequence;
            long diff = nodeSeq - (currentReadSeq + 1);
            
            if (diff == 0) {
                // Item is available
                if (readSequence.compareAndSet(currentReadSeq, currentReadSeq + 1)) {
                    break;
                }
            } else if (diff < 0) {
                // No item available
                return null;
            }
        }
        
        T data = node.data;
        node.data = null;
        node.sequence = currentReadSeq + capacity;
        
        System.out.println("Polled: " + data + " at sequence " + currentReadSeq + 
                         " by " + Thread.currentThread().getName());
        return data;
    }
    
    public int size() {
        long write = writeSequence.get();
        long read = readSequence.get();
        return (int) Math.max(0, write - read);
    }
    
    public boolean isEmpty() {
        return writeSequence.get() == readSequence.get();
    }
    
    public boolean isBackpressureActive() {
        return backpressureActive.get();
    }
    
    public long getDroppedItemsCount() {
        return droppedItems.get();
    }
    
    public void printStatistics() {
        System.out.println("=== Queue Statistics ===");
        System.out.println("Capacity: " + capacity);
        System.out.println("Current size: " + size());
        System.out.println("Write sequence: " + writeSequence.get());
        System.out.println("Read sequence: " + readSequence.get());
        System.out.println("Backpressure active: " + backpressureActive.get());
        System.out.println("Dropped items: " + droppedItems.get());
    }
    
    // Adaptive producer that responds to backpressure
    static class AdaptiveProducer<T> implements Runnable {
        private final LockFreeBackpressureQueue<T> queue;
        private final String name;
        private final T[] items;
        private volatile boolean running = true;
        private int producedCount = 0;
        private int droppedCount = 0;
        
        @SuppressWarnings("unchecked")
        public AdaptiveProducer(LockFreeBackpressureQueue<T> queue, String name, T[] items) {
            this.queue = queue;
            this.name = name;
            this.items = items;
        }
        
        @Override
        public void run() {
            int itemIndex = 0;
            int sleepTime = 10; // Initial sleep time
            
            while (running && itemIndex < items.length) {
                T item = items[itemIndex];
                
                if (queue.offer(item, true)) { // Drop on backpressure
                    producedCount++;
                    itemIndex++;
                    
                    // Reduce sleep time on successful offer
                    sleepTime = Math.max(1, sleepTime - 1);
                } else {
                    droppedCount++;
                    
                    // Increase sleep time on backpressure
                    sleepTime = Math.min(100, sleepTime + 5);
                }
                
                try {
                    Thread.sleep(sleepTime);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    break;
                }
            }

                             ", Dropped: " + droppedCount);
```

## Key Takeaways

1. **Lock-free vs Lock-based**: Lock-free mechanisms provide better scalability and avoid blocking but are more complex to implement correctly.
   - **Technical Insight**: Lock-free algorithms provide progress guarantees (wait-free, lock-free, obstruction-free) that prevent threads from blocking indefinitely. They use atomic primitives and memory ordering to achieve consistency without mutual exclusion.

2. **CAS Operations**: The foundation of lock-free programming, providing atomic compare-and-swap operations that enable wait-free algorithms.
   - **Technical Insight**: CAS maps to single CPU instructions (CMPXCHG on x86, LDREX/STREX on ARM) that atomically compare memory location with expected value and update if match. Includes implicit memory barriers for proper ordering.

3. **ABA Problem**: A common issue in lock-free programming that can be solved using stamped references or careful algorithm design.
   - **Technical Insight**: Occurs when memory location changes from A→B→A between CAS operations, making the change invisible. Solutions include AtomicStampedReference for version control or hazard pointers for safe memory reclamation.

4. **Performance Trade-offs**: Lock-free structures excel under high contention but may have overhead in low-contention scenarios.
   - **Technical Insight**: Lock-free structures avoid context switching overhead (~1000+ cycles) but may suffer from retry loops under contention. Optimal performance depends on contention level, CPU core count, and cache coherency protocols.

5. **Atomic Classes**: Java provides comprehensive atomic classes that handle most common lock-free programming needs.
   - **Technical Insight**: Built on Unsafe/VarHandle for direct memory access. Use specialized implementations: AtomicInteger for simple counters, LongAdder for high-contention scenarios, AtomicReference for object references.

6. **Memory Ordering**: Understanding memory consistency and ordering is crucial for correct lock-free implementations.
   - **Technical Insight**: Lock-free algorithms must consider memory reordering by CPU and compiler. Use acquire/release semantics, memory barriers, and happens-before relationships to ensure proper visibility and ordering.

7. **Complexity Management**: Lock-free programming requires careful design and testing due to subtle race conditions and edge cases.
   - **Technical Insight**: Requires understanding of linearization points, helping protocols, memory reclamation strategies, and formal verification techniques. Testing must account for rare interleavings and timing-dependent bugs.

### 🔬 **Advanced Technical Concepts**

**Hardware-Level Considerations**:
- **CPU Architecture**: Different architectures (x86, ARM, POWER) have varying atomic instruction support and memory models
- **Cache Coherency**: MESI protocol ensures atomicity across cores but adds overhead for shared cache lines
- **False Sharing**: Careful data structure layout prevents performance degradation from cache line conflicts
- **NUMA Awareness**: Memory access patterns matter on Non-Uniform Memory Access architectures

**Memory Management**:
- **Hazard Pointers**: Technique for safe memory reclamation in lock-free data structures
- **Epoch-Based Reclamation**: Alternative approach using global epochs for memory management
- **Reference Counting**: Atomic reference counting for automatic memory management
- **Memory Barriers**: Explicit control over memory ordering using acquire/release semantics

**Algorithm Design Patterns**:
- **Helping Protocols**: Threads help complete other threads' operations to ensure progress
- **Backoff Strategies**: Exponential, linear, or random backoff to reduce contention
- **Optimistic Concurrency**: Assume low contention and handle conflicts when they occur
- **Lock-Free Data Structures**: Stacks, queues, hash tables, and trees with lock-free implementations

**Performance Optimization**:
```
Scenario              | Lock-based | Lock-free | Optimal Choice
----------------------|------------|-----------|----------------

```

**Debugging and Testing**:
- **Race Condition Detection**: Tools like ThreadSanitizer, Helgrind for detecting data races
- **Stress Testing**: High-contention scenarios to expose timing-dependent bugs
- **Formal Verification**: Model checking and theorem proving for correctness guarantees
- **Linearizability Testing**: Verify that concurrent operations appear atomic
