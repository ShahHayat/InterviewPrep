## Introduction

Thread management is fundamental to concurrent programming in Java. This document explores the various ways to create threads, their lifecycle states, and mechanisms for inter-thread communication.

### 🎯 **What You'll Learn**
- **Thread Creation**: Different ways to create and start threads in Java
- **Thread Lifecycle**: How threads transition between different states (NEW, RUNNABLE, BLOCKED, etc.)
- **Inter-thread Communication**: How threads can coordinate and communicate with each other
- **Best Practices**: When to use which approach and common pitfalls to avoid

### 💡 **Simple Analogy**
Think of threads like **workers in a restaurant**:
- **Creating threads** = Hiring workers (different ways to hire: full-time, part-time, contractors)
- **Thread lifecycle** = Worker states (available, working, on break, finished shift)
- **Communication** = Workers coordinating (chef tells waiter when food is ready)

### 1. Extending Thread Class

**🎯 When to Use**: When you need full control over thread behavior and don't need to extend another class.
**⚠️ Limitation**: Java single inheritance - you can't extend another class if you extend Thread.

**🔧 Technical Deep Dive**:
- **Class Hierarchy**: Thread class implements Runnable interface and provides native methods for OS thread management
- **Native Implementation**: `start()` method calls native `start0()` which creates actual OS thread via JNI (Java Native Interface)
- **Memory Model**: Each Thread object maintains its own Thread Control Block (TCB) with thread-specific data
- **Inheritance Limitation**: Due to Java's single inheritance model, extending Thread prevents extending domain-specific classes
- **Resource Management**: Thread objects hold references to native resources that must be properly cleaned up by GC

```java
public class MyThread extends Thread {
    private String threadName;
    
    public MyThread(String name) {
        this.threadName = name;
    }
    
    @Override
    public void run() {
        System.out.println("Thread " + threadName + " is running");
        for (int i = 0; i < 5; i++) {
            System.out.println(threadName + ": " + i);
            try {
                Thread.sleep(1000);
            } catch (InterruptedException e) {
                System.out.println(threadName + " interrupted");
                Thread.currentThread().interrupt();
                return;
            }
        }
        System.out.println(threadName + " finished");
    }
}

// Usage
public class ThreadExample {
    public static void main(String[] args) {
        MyThread thread1 = new MyThread("Thread-1");
        MyThread thread2 = new MyThread("Thread-2");
        
        thread1.start();
        thread2.start();
    }
}
```

### 2. Implementing Runnable Interface

**🎯 When to Use**: Preferred approach - allows your class to extend another class and promotes better design.
**✅ Benefits**: Better separation of concerns, more flexible design.

**🔧 Technical Deep Dive**:
- **Functional Interface**: Runnable is a functional interface with single abstract method `run()`, making it lambda-compatible
- **Composition over Inheritance**: Follows composition principle - task logic separated from thread management
- **Thread Pool Compatibility**: Runnable tasks can be executed by ExecutorService without creating new Thread objects
- **Memory Efficiency**: Multiple Runnable instances can share same Thread object, reducing memory overhead
- **Design Pattern**: Implements Strategy pattern - algorithm (task) is encapsulated and can be passed around
- **JVM Optimization**: HotSpot JVM can better optimize Runnable tasks in thread pools through escape analysis

```java
public class MyRunnable implements Runnable {
    private String taskName;
    
    public MyRunnable(String name) {
        this.taskName = name;
    }
    
    @Override
    public void run() {
        System.out.println("Task " + taskName + " started by " + 
                          Thread.currentThread().getName());
        
        for (int i = 0; i < 5; i++) {
            System.out.println(taskName + ": " + i);
            try {
                Thread.sleep(500);
            } catch (InterruptedException e) {
                System.out.println(taskName + " interrupted");
                Thread.currentThread().interrupt();
                return;
            }
        }
        System.out.println(taskName + " completed");
    }
}

// Usage
```

### 3. Using Lambda Expressions (Java 8+)

**🔧 Technical Deep Dive**:
- **Bytecode Generation**: Lambda expressions are compiled to invokedynamic instructions with method handles
- **Capture Semantics**: Lambdas can capture effectively final local variables and instance variables
- **Functional Interface Target**: Lambda must target functional interface (interface with single abstract method)
- **Method Reference Optimization**: Method references (::) can be more efficient than equivalent lambda expressions
- **Bootstrap Method**: JVM uses bootstrap method to create lambda instances at runtime via LambdaMetafactory
- **Performance**: Lambdas have minimal overhead compared to anonymous classes due to invokedynamic optimization

```java
public class LambdaThreadExample {
    public static void main(String[] args) {
        // Method 1: Lambda with Runnable
        Thread thread1 = new Thread(() -> {
            String threadName = Thread.currentThread().getName();
            for (int i = 0; i < 3; i++) {
                System.out.println(threadName + ": " + i);
                try {
                    Thread.sleep(1000);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    return;
                }
            }
        }, "Lambda-Thread-1");
        
        // Method 2: Method reference
        Thread thread2 = new Thread(LambdaThreadExample::printNumbers, "Lambda-Thread-2");
        
        thread1.start();
        thread2.start();
    }
    
    private static void printNumbers() {
        String threadName = Thread.currentThread().getName();
        for (int i = 10; i < 13; i++) {
            System.out.println(threadName + ": " + i);
            try {
                Thread.sleep(800);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                return;
            }
        }
    }
}
```

### 4. Using Callable and Future

**🔧 Technical Deep Dive**:
- **Generic Return Type**: Callable<V> allows parameterized return types, providing type safety at compile time
- **Exception Propagation**: Unlike Runnable, Callable can throw checked exceptions that are wrapped in ExecutionException
- **Future Pattern**: Implements Future pattern for asynchronous computation with result retrieval
- **Blocking Operations**: Future.get() blocks calling thread until result is available or timeout occurs
- **Cancellation Support**: Future provides cancellation mechanism with mayInterruptIfRunning flag
- **Memory Visibility**: Future.get() establishes happens-before relationship ensuring visibility of task results
- **FutureTask Implementation**: FutureTask uses AbstractQueuedSynchronizer (AQS) for state management and thread coordination

```java
        @Override
        public Integer call() throws Exception {
            System.out.println("Calculating factorial of " + number + 
                             " in thread: " + Thread.currentThread().getName());
            
            int result = 1;
            for (int i = 1; i <= number; i++) {
                result *= i;
                Thread.sleep(100); // Simulate work
            }
            
            return result;
        }
    }

            Future<Integer> future2 = executor.submit(new NumberCalculator(7));
```

## Thread Lifecycle

**🔄 Understanding Thread States**: Threads go through different states during their lifetime, like employees during a workday.

**🔧 Technical Deep Dive - Thread State Management**:
- **State Storage**: Thread state is stored in Thread object and maintained by JVM thread scheduler
- **Atomic Transitions**: State transitions are atomic operations managed by JVM using native synchronization
- **OS Thread Mapping**: Java thread states map to underlying OS thread states but provide additional abstraction
- **Memory Barriers**: State transitions involve memory barriers to ensure visibility across threads
- **Scheduler Integration**: Thread scheduler uses state information for scheduling decisions and resource allocation
- **JVM Implementation**: Different JVM implementations may have slight variations in state transition timing

**🏢 Office Worker Analogy**:
- **NEW**: Employee hired but hasn't started work yet
- **RUNNABLE**: Employee is working or ready to work  
- **BLOCKED**: Employee waiting for meeting room (resource)
- **WAITING**: Employee waiting for colleague indefinitely
- **TIMED_WAITING**: Employee on scheduled lunch break
- **TERMINATED**: Employee finished work and left

**⚙️ Technical State Details**:

1. **NEW State**:
   - **Memory Allocation**: Thread object created in heap, stack space allocated but not initialized
   - **Native Resources**: No OS thread created yet, minimal resource consumption
   - **Scheduler State**: Not registered with thread scheduler
   - **Transition**: start() method creates OS thread and moves to RUNNABLE

2. **RUNNABLE State**:
   - **Sub-states**: Actually running on CPU or ready to run (in ready queue)
   - **Scheduler Control**: Subject to OS thread scheduler time-slicing and preemption
   - **CPU Time**: May be executing instructions or waiting for CPU allocation
   - **I/O Operations**: Non-blocking I/O operations keep thread in RUNNABLE state

3. **BLOCKED State**:
   - **Monitor Lock**: Waiting to acquire intrinsic lock (synchronized block/method)
   - **Entry Set**: Thread is in monitor's entry set, competing for lock acquisition
   - **No CPU Time**: Thread is not scheduled for CPU time while blocked
   - **FIFO Ordering**: Usually first-in-first-out ordering for lock acquisition

4. **WAITING State**:
   - **Conditional Waiting**: Waiting for specific condition or event
   - **Wait Set**: For wait(), thread is in monitor's wait set
   - **No Timeout**: Will wait indefinitely until condition is met
   - **Memory Release**: wait() releases monitor lock and flushes changes to main memory

5. **TIMED_WAITING State**:
   - **Timeout Mechanism**: JVM maintains timeout tracking for each thread
   - **Timer Integration**: Integrated with OS timer facilities for efficient timeout handling
   - **Early Wakeup**: Can be awakened before timeout by notify() or interrupt()
   - **Resource Management**: Timeout threads managed efficiently to avoid resource leaks

6. **TERMINATED State**:
   - **Resource Cleanup**: Stack memory deallocated, native resources freed
   - **GC Eligible**: Thread object becomes eligible for garbage collection
   - **Join Completion**: Threads waiting on join() are notified
   - **Final State**: No transitions possible from TERMINATED state

```java
        }

        // TERMINATED state
        System.out.println("4. Thread state: " + thread.getState()); // TERMINATED
    }
```

## Inter-thread Communication

**🔧 Technical Overview - Inter-thread Communication Mechanisms**:
- **Shared Memory Model**: Threads communicate through shared memory locations with synchronization primitives
- **Memory Visibility**: Communication requires proper synchronization to ensure memory visibility across threads
- **Happens-Before Relationships**: Communication mechanisms establish happens-before relationships for ordering guarantees
- **Blocking vs Non-blocking**: Different mechanisms provide blocking or non-blocking communication patterns
- **Fairness Guarantees**: Some mechanisms provide fairness guarantees to prevent thread starvation
- **Performance Trade-offs**: Each mechanism has different performance characteristics and use case suitability

### 1. Wait-Notify Mechanism

**🔧 Technical Deep Dive - Wait/Notify Implementation**:
- **Monitor Pattern**: Implements monitor synchronization pattern with condition variables
- **Intrinsic Locks**: Uses object's intrinsic lock (monitor) for synchronization
- **Wait Set Management**: JVM maintains wait set for each object monitor
- **Spurious Wakeups**: wait() can return spuriously, requiring loop-based condition checking
- **Memory Synchronization**: wait() and notify() establish happens-before relationships
- **Native Implementation**: Backed by OS condition variables and mutex primitives
- **Lock Release**: wait() atomically releases monitor lock and suspends thread
- **Signal Semantics**: notify() moves one thread from wait set to entry set, notifyAll() moves all threads

```java
public class WaitNotifyExample {
    private static final Object lock = new Object();
    private static boolean dataReady = false;
    private static String sharedData;
    
    static class Producer implements Runnable {
        @Override
        public void run() {
            synchronized (lock) {
                System.out.println("Producer: Preparing data...");
                try {
                    Thread.sleep(2000); // Simulate data preparation
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    return;
                }
                
                sharedData = "Important Data from Producer";
                dataReady = true;
                
                System.out.println("Producer: Data ready, notifying consumers");
                lock.notifyAll(); // Notify all waiting threads
            }
        }
    }
    
    static class Consumer implements Runnable {
        private String name;
        
        public Consumer(String name) {
            this.name = name;
        }
        
        @Override
        public void run() {
            synchronized (lock) {
                System.out.println(name + ": Waiting for data...");
                
                while (!dataReady) {
                    try {
                        lock.wait(); // Release lock and wait
                    } catch (InterruptedException e) {
                        Thread.currentThread().interrupt();
                        return;
                    }
                }
                
                System.out.println(name + ": Received data: " + sharedData);
            }
        }
    }

        Thread consumer1 = new Thread(new Consumer("Consumer-1"));
        Thread consumer2 = new Thread(new Consumer("Consumer-2"));

        consumer1.start();
        consumer2.start();
        
        Thread.sleep(1000);
        
        // Start producer
        producer.start();
        
        // Wait for all threads to complete
        producer.join();
```

```java
import java.util.concurrent.*;

public class BlockingQueueCommunication {
    private static final BlockingQueue<String> queue = new ArrayBlockingQueue<>(10);
    
    static class Producer implements Runnable {
        @Override
        public void run() {
            try {
                for (int i = 1; i <= 5; i++) {
                    String message = "Message-" + i;
                    queue.put(message); // Blocks if queue is full
                    System.out.println("Producer sent: " + message);
                    Thread.sleep(1000);
                }
                
                queue.put("STOP"); // Signal to stop consumers
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
    }
    
    static class Consumer implements Runnable {
        private String name;
        
        public Consumer(String name) {
            this.name = name;
        }
        
        @Override
        public void run() {
            try {
                while (true) {
                    String message = queue.take(); // Blocks if queue is empty
                    
                    if ("STOP".equals(message)) {
                        queue.put(message); // Put it back for other consumers
                        break;
                    }
                    
                    System.out.println(name + " received: " + message);
                    Thread.sleep(1500);
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
    }
    
    public static void main(String[] args) throws InterruptedException {
        Thread producer = new Thread(new Producer());
        Thread consumer1 = new Thread(new Consumer("Consumer-1"));
        Thread consumer2 = new Thread(new Consumer("Consumer-2"));
        
        producer.start();
        consumer1.start();
        consumer2.start();
        
        producer.join();
        consumer1.join();
        consumer2.join();
    }
}
```

### 3. CountDownLatch Communication

**🔧 Technical Deep Dive - CountDownLatch Implementation**:
- **AbstractQueuedSynchronizer (AQS)**: Built on AQS framework for efficient synchronization
- **Shared Mode**: Uses AQS shared mode allowing multiple threads to wait simultaneously
- **Atomic Counter**: Maintains atomic counter that decrements on countDown() calls
- **One-time Use**: Cannot be reset once counter reaches zero - single-use synchronization primitive
- **Memory Ordering**: await() and countDown() provide memory ordering guarantees
- **Efficient Blocking**: Uses LockSupport.park() for efficient thread suspension
- **CAS Operations**: Counter updates use Compare-And-Swap for lock-free atomic operations
- **Fairness**: No fairness guarantees - awakened threads compete for CPU resources

### 4. CyclicBarrier Communication

**🔧 Technical Deep Dive - CyclicBarrier Implementation**:
- **Reusable Synchronization**: Unlike CountDownLatch, CyclicBarrier can be reused for multiple synchronization points
- **ReentrantLock Based**: Uses ReentrantLock and Condition for thread coordination
- **Generation Concept**: Maintains generation number to handle barrier reuse and broken barriers
- **Barrier Action**: Optional Runnable executed by last thread reaching barrier
- **All-or-Nothing**: All threads must reach barrier or it becomes broken
- **Exception Handling**: BrokenBarrierException thrown when barrier is broken
- **Timeout Support**: await() supports timeout with TimeUnit specification
- **Thread Interruption**: Interrupted threads cause barrier to become broken, affecting all waiting threads

```java
import java.util.concurrent.CyclicBarrier;
import java.util.concurrent.BrokenBarrierException;

public class CyclicBarrierExample {
    private static final int THREAD_COUNT = 4;
    private static final CyclicBarrier barrier = new CyclicBarrier(THREAD_COUNT, () -> {
        System.out.println("*** All threads reached barrier, barrier action executed ***");
    });
    
    static class Task implements Runnable {
        private int taskId;
        
        public Task(int taskId) {
            this.taskId = taskId;
        }
        
        @Override
        public void run() {
            try {
                for (int phase = 1; phase <= 3; phase++) {
                    System.out.println("Task " + taskId + " working on phase " + phase);
                    
                    // Simulate work
                    Thread.sleep((long) (Math.random() * 2000 + 1000));
                    
                    System.out.println("Task " + taskId + " completed phase " + phase + 
                                     ", waiting at barrier");
                    
                    barrier.await(); // Wait for all threads to reach this point
                    
                    System.out.println("Task " + taskId + " proceeding after barrier");
                }
            } catch (InterruptedException | BrokenBarrierException e) {
                Thread.currentThread().interrupt();
                System.err.println("Task " + taskId + " interrupted: " + e.getMessage());
            }
        }
    }
    
    public static void main(String[] args) {
        System.out.println("Starting " + THREAD_COUNT + " tasks");
        
        for (int i = 1; i <= THREAD_COUNT; i++) {
            new Thread(new Task(i)).start();
        }
    }
}
```

### 5. Semaphore Communication

**🔧 Technical Deep Dive - Semaphore Implementation**:
- **Counting Semaphore**: Maintains count of available permits for resource access control
- **AQS Framework**: Built on AbstractQueuedSynchronizer for efficient permit management
- **Fair vs Unfair**: Supports both fair (FIFO) and unfair permit acquisition policies
- **Atomic Operations**: Permit acquisition and release use atomic compare-and-swap operations
- **Blocking Acquire**: acquire() blocks when no permits available, uses LockSupport.park()
- **Non-blocking Variants**: tryAcquire() provides non-blocking permit acquisition with optional timeout
- **Bulk Operations**: Supports acquiring/releasing multiple permits atomically
- **Memory Consistency**: Acquire and release operations establish happens-before relationships

```java
import java.util.concurrent.Semaphore;

public class SemaphoreExample {
    private static final Semaphore semaphore = new Semaphore(2); // Allow 2 concurrent accesses
    
    static class Resource {
        private static int resourceId = 0;
        
        public static void access(String threadName) {
            try {
                System.out.println(threadName + " requesting access to resource");
                semaphore.acquire(); // Acquire permit
                
                int currentResourceId = ++resourceId;
                System.out.println(threadName + " acquired resource " + currentResourceId);
                
                // Simulate resource usage
                Thread.sleep(3000);
                
                System.out.println(threadName + " releasing resource " + currentResourceId);
                
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            } finally {
                semaphore.release(); // Release permit
            }
        }
    }
    
    public static void main(String[] args) {
        for (int i = 1; i <= 5; i++) {
            final String threadName = "Thread-" + i;
            new Thread(() -> Resource.access(threadName)).start();
        }
    }
}
```

## Advantages and Disadvantages

### Thread Creation Methods Comparison

**🔧 Technical Analysis of Thread Creation Approaches**:

| Method | Advantages | Disadvantages | Technical Details |
|--------|------------|---------------|-------------------|
| **Extending Thread** | Simple, direct access to thread methods | Single inheritance limitation, tight coupling | **Memory**: Each Thread object ~2KB overhead<br/>**Performance**: Direct method calls, no delegation<br/>**JVM**: Native thread mapping 1:1 |
| **Implementing Runnable** | Better design, supports multiple inheritance | Requires Thread wrapper, no direct thread control | **Memory**: Runnable objects ~200 bytes<br/>**Performance**: Method delegation overhead<br/>**Pool Compatibility**: Works with ExecutorService |
| **Lambda Expressions** | Concise, functional programming style | Limited to simple tasks, less readable for complex logic | **Bytecode**: invokedynamic instruction<br/>**Performance**: Minimal lambda overhead<br/>**Capture**: Effectively final variable capture |
| **Callable/Future** | Returns results, exception handling | More complex, requires ExecutorService | **Memory**: FutureTask uses AQS (~1KB)<br/>**Performance**: Additional synchronization overhead<br/>**Exception**: Checked exception propagation |
| **Thread Factory** | Customizable thread creation, centralized configuration | Additional complexity, overhead | **Pattern**: Factory design pattern<br/>**Customization**: Name, priority, daemon status<br/>**Integration**: Thread pool integration |

### Inter-thread Communication Methods

**🔧 Technical Analysis of Communication Mechanisms**:

| Method | Advantages | Disadvantages | Technical Details |
|--------|------------|---------------|-------------------|
| **Wait/Notify** | Low-level control, efficient | Complex, error-prone, requires synchronization | **Implementation**: Native OS condition variables<br/>**Memory**: No additional overhead<br/>**Performance**: ~100ns per operation<br/>**Spurious Wakeups**: Requires loop-based checking |

### 2. Bank Transaction System

```java
import java.util.concurrent.locks.ReentrantLock;
import java.util.concurrent.atomic.AtomicLong;

public class BankTransactionSystem {
    static class BankAccount {
        private final String accountId;
        private volatile double balance;
        private final ReentrantLock lock = new ReentrantLock();
        private static final AtomicLong transactionCounter = new AtomicLong(0);
        
        public BankAccount(String accountId, double initialBalance) {
            this.accountId = accountId;
            this.balance = initialBalance;
        }
        
        public boolean withdraw(double amount) {
            lock.lock();
            try {
                if (balance >= amount) {
                    System.out.println("Withdrawing " + amount + " from " + accountId + 
                                     " by " + Thread.currentThread().getName());
                    
                    // Simulate processing time
                    Thread.sleep(100);
                    
                    balance -= amount;
                    System.out.println("Withdrawal successful. New balance: " + balance);
                    return true;
                } else {
                    System.out.println("Insufficient funds in " + accountId + 
                                     " for withdrawal of " + amount);
                    return false;
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                return false;
            } finally {
                lock.unlock();
            }
        }
        
        public void deposit(double amount) {
            lock.lock();
            try {
                System.out.println("Depositing " + amount + " to " + accountId + 
                                 " by " + Thread.currentThread().getName());
                
                // Simulate processing time
                Thread.sleep(100);
                
                balance += amount;
                System.out.println("Deposit successful. New balance: " + balance);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            } finally {
                lock.unlock();
            }
        }
        
        public double getBalance() {
            lock.lock();
            try {
                return balance;
            } finally {
                lock.unlock();
            }
        }
        
        public static boolean transfer(BankAccount from, BankAccount to, double amount) {
            long transactionId = transactionCounter.incrementAndGet();
            System.out.println("Starting transfer #" + transactionId + ": " + amount + 
                             " from " + from.accountId + " to " + to.accountId);
            
            // Always acquire locks in the same order to prevent deadlock
            BankAccount firstLock = from.accountId.compareTo(to.accountId) < 0 ? from : to;
            BankAccount secondLock = from.accountId.compareTo(to.accountId) < 0 ? to : from;
            
            firstLock.lock.lock();
            try {
                secondLock.lock.lock();
                try {
                    if (from.balance >= amount) {
                        from.balance -= amount;
                        to.balance += amount;
                        
                        System.out.println("Transfer #" + transactionId + " completed successfully");
                        System.out.println(from.accountId + " balance: " + from.balance);
                        System.out.println(to.accountId + " balance: " + to.balance);
                        return true;
                    } else {
                        System.out.println("Transfer #" + transactionId + " failed: insufficient funds");
                        return false;
                    }
                } finally {
                    secondLock.lock.unlock();
                }
            } finally {
                firstLock.lock.unlock();
            }
        }
    }
    
    public static void main(String[] args) throws InterruptedException {
        BankAccount account1 = new BankAccount("ACC-001", 1000.0);
```

### Problem 1: Dining Philosophers with Timeout

```java
import java.util.concurrent.TimeUnit;
import java.util.concurrent.locks.ReentrantLock;

public class DiningPhilosophersWithTimeout {
    private static final int NUM_PHILOSOPHERS = 5;
    private static final ReentrantLock[] forks = new ReentrantLock[NUM_PHILOSOPHERS];
    
    static {
        for (int i = 0; i < NUM_PHILOSOPHERS; i++) {
            forks[i] = new ReentrantLock();
        }
    }
    
    static class Philosopher implements Runnable {
        private final int id;
        private int mealsEaten = 0;
        private final int maxMeals = 3;
        
        public Philosopher(int id) {
            this.id = id;
        }
        
        @Override
        public void run() {
            try {
                while (mealsEaten < maxMeals) {
                    think();
                    if (eat()) {
                        mealsEaten++;
                        System.out.println("Philosopher " + id + " has eaten " + mealsEaten + " meals");
                    } else {
                        System.out.println("Philosopher " + id + " couldn't get forks, continuing to think");
                    }
                }
                System.out.println("Philosopher " + id + " finished eating and left");
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                System.out.println("Philosopher " + id + " was interrupted");
            }
        }
        
        private void think() throws InterruptedException {
            System.out.println("Philosopher " + id + " is thinking");
            Thread.sleep((long) (Math.random() * 1000 + 500));
        }
        
        private boolean eat() throws InterruptedException {
            int leftFork = id;
            int rightFork = (id + 1) % NUM_PHILOSOPHERS;
            
            // Try to acquire both forks with timeout
            boolean gotLeftFork = forks[leftFork].tryLock(2, TimeUnit.SECONDS);
            if (!gotLeftFork) {
                return false;
            }
            
            try {
                boolean gotRightFork = forks[rightFork].tryLock(2, TimeUnit.SECONDS);
                if (!gotRightFork) {
                    return false;
                }
                
                try {
                    System.out.println("Philosopher " + id + " is eating");
                    Thread.sleep((long) (Math.random() * 1000 + 500));
                    return true;
                } finally {
                    forks[rightFork].unlock();
                }
            } finally {
                forks[leftFork].unlock();
            }
        }
    }
    
    public static void main(String[] args) throws InterruptedException {
        Thread[] philosophers = new Thread[NUM_PHILOSOPHERS];
        
        for (int i = 0; i < NUM_PHILOSOPHERS; i++) {
            philosophers[i] = new Thread(new Philosopher(i), "Philosopher-" + i);
            philosophers[i].start();
        }
        
        for (Thread philosopher : philosophers) {
            philosopher.join();
        }
        
        System.out.println("All philosophers finished");
    }
```

### Problem 2: Producer-Consumer with Priority

```java
import java.util.concurrent.PriorityBlockingQueue;
import java.util.concurrent.atomic.AtomicInteger;

public class PriorityProducerConsumer {
    static class Task implements Comparable<Task> {
        private final int priority;
        private final String data;
        private final long timestamp;
        private static final AtomicInteger taskCounter = new AtomicInteger(0);
        private final int taskId;
        
        public Task(int priority, String data) {
            this.priority = priority;
            this.data = data;
            this.timestamp = System.currentTimeMillis();
            this.taskId = taskCounter.incrementAndGet();
        }
        
        @Override
        public int compareTo(Task other) {
            // Higher priority first, then by timestamp (FIFO for same priority)
            int priorityCompare = Integer.compare(other.priority, this.priority);
            if (priorityCompare != 0) {
                return priorityCompare;
            }
            return Long.compare(this.timestamp, other.timestamp);
        }
        
        @Override
        public String toString() {
            return String.format("Task[id=%d, priority=%d, data='%s']", taskId, priority, data);
        }
        
        public int getPriority() { return priority; }
        public String getData() { return data; }
    }
    
    private static final PriorityBlockingQueue<Task> taskQueue = new PriorityBlockingQueue<>();
    private static volatile boolean shutdown = false;
    
    static class Producer implements Runnable {
        private final String name;
        
        public Producer(String name) {
            this.name = name;
        }
        
        @Override
        public void run() {
            try {
                for (int i = 0; i < 10; i++) {
                    int priority = (int) (Math.random() * 10) + 1; // Priority 1-10
                    Task task = new Task(priority, name + "-Task-" + i);
                    
                    taskQueue.put(task);
                    System.out.println(name + " produced: " + task);
                    
                    Thread.sleep(500);
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
    }
    
    static class Consumer implements Runnable {
        private final String name;
        
        public Consumer(String name) {
            this.name = name;
        }
        
        @Override
        public void run() {
            try {
                while (!shutdown || !taskQueue.isEmpty()) {
                    Task task = taskQueue.poll(1, java.util.concurrent.TimeUnit.SECONDS);
                    if (task != null) {
                        System.out.println(name + " consuming: " + task);
                        
                        // Simulate processing time based on priority
                        long processingTime = (11 - task.getPriority()) * 100; // Higher priority = less time
                        Thread.sleep(processingTime);
                        
                        System.out.println(name + " completed: " + task);
                    }
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
    }
    
    public static void main(String[] args) throws InterruptedException {
        // Start producers
        Thread producer1 = new Thread(new Producer("Producer-1"));
        Thread producer2 = new Thread(new Producer("Producer-2"));
        
        // Start consumers
        Thread consumer1 = new Thread(new Consumer("Consumer-1"));
        Thread consumer2 = new Thread(new Consumer("Consumer-2"));
        
        producer1.start();
        producer2.start();
        consumer1.start();
        consumer2.start();
        
        // Wait for producers to finish
        producer1.join();
        producer2.join();
        
        // Allow some time for consumers to process remaining tasks
        Thread.sleep(2000);
        
        // Signal shutdown
        shutdown = true;
        
        // Wait for consumers to finish
        consumer1.join();
        consumer2.join();
        
        System.out.println("All tasks processed. Remaining tasks: " + taskQueue.size());
    }
```

```java
import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.ReentrantLock;

public class WriterPreferenceReadWriteLock {
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition readCondition = lock.newCondition();
    private final Condition writeCondition = lock.newCondition();
    
    private int readers = 0;
    private int writers = 0;
    private int waitingWriters = 0;
    private boolean writing = false;
    
    public void readLock() throws InterruptedException {
        lock.lock();
        try {
            while (writing || waitingWriters > 0) {
                readCondition.await();
            }
            readers++;
        } finally {
            lock.unlock();
        }
    }
    
    public void readUnlock() {
        lock.lock();
        try {
            readers--;
            if (readers == 0) {
                writeCondition.signalAll();
            }
        } finally {
            lock.unlock();
        }
    }
    
    public void writeLock() throws InterruptedException {
        lock.lock();
        try {
            waitingWriters++;
            while (readers > 0 || writing) {
                writeCondition.await();
            }
            waitingWriters--;
            writing = true;
            writers++;
        } finally {
            lock.unlock();
        }
    }
    
    public void writeUnlock() {
        lock.lock();
        try {
            writing = false;
            writers--;
            writeCondition.signalAll();
            readCondition.signalAll();
        } finally {
            lock.unlock();
        }
    }
    
    // Test the custom read-write lock
    static class SharedResource {
        private static final WriterPreferenceReadWriteLock rwLock = new WriterPreferenceReadWriteLock();
        private static String data = "Initial Data";
        private static int version = 0;
        
        public static String read(String readerName) throws InterruptedException {
            rwLock.readLock();
            try {
                System.out.println(readerName + " reading: " + data + " (version " + version + ")");
                Thread.sleep(1000); // Simulate read operation
                return data;
            } finally {
                rwLock.readUnlock();
                System.out.println(readerName + " finished reading");
            }
        }
        
        public static void write(String writerName, String newData) throws InterruptedException {
            rwLock.writeLock();
            try {
                System.out.println(writerName + " writing: " + newData);
                Thread.sleep(2000); // Simulate write operation
                data = newData;
                version++;
                System.out.println(writerName + " finished writing (version " + version + ")");
            } finally {
                rwLock.writeUnlock();
            }
        }
    }
    
    public static void main(String[] args) throws InterruptedException {
        // Start multiple readers
        for (int i = 1; i <= 5; i++) {
            final int readerId = i;
            new Thread(() -> {

                    for (int j = 0; j < 3; j++) {
                        SharedResource.read("Reader-" + readerId);
                        Thread.sleep(500);
                    }
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }).start();
        }
        
        // Start multiple writers
        for (int i = 1; i <= 2; i++) {

                                           "Data from Writer-" + writerId + " iteration " + j);
                        Thread.sleep(1000);
                    }
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }).start();
        }
    }
```

## Key Takeaways

1. **Choose the Right Creation Method**: Use Runnable for better design, Callable for return values, and Thread factories for custom configuration.
   - **Technical Insight**: Runnable promotes composition over inheritance, allowing better OOP design and thread pool compatibility. Thread creation overhead varies: Thread objects (~2KB), Runnable (~200 bytes), Lambda (minimal bytecode overhead).

2. **Understand Thread Lifecycle**: Proper understanding of thread states helps in debugging and optimization.
   - **Technical Insight**: Thread state transitions are atomic operations managed by JVM scheduler. State information is crucial for debugging deadlocks, performance bottlenecks, and resource leaks. Use ThreadMXBean for programmatic thread monitoring.

3. **Use Appropriate Communication Mechanism**: Choose based on your specific needs - wait/notify for low-level control, BlockingQueue for producer-consumer, etc.
   - **Technical Insight**: Each mechanism has different performance characteristics: wait/notify (~100ns), semaphore (~100ns), CountDownLatch (~50ns), BlockingQueue (~500ns). Consider fairness requirements and scalability needs.

4. **Handle Interruption Properly**: Always check for interruption and restore the interrupt status.
   - **Technical Insight**: Thread interruption is cooperative - threads must check interrupted flag. InterruptedException clears the flag, so Thread.currentThread().interrupt() should be called to restore it. Improper handling can lead to resource leaks.

5. **Avoid Deadlocks**: Use consistent lock ordering and consider timeouts for lock acquisition.
   - **Technical Insight**: Deadlock detection is expensive in JVM. Prevention strategies include: consistent lock ordering, timeout-based acquisition (tryLock), deadlock detection algorithms, and avoiding nested locks when possible.

6. **Monitor Thread States**: Use tools like ThreadMXBean for monitoring and debugging concurrent applications.
   - **Technical Insight**: ThreadMXBean provides programmatic access to thread information including CPU time, blocked time, wait count, and stack traces. Essential for performance profiling and deadlock detection.
